# 开发路线

更新日期：2026-10-23。当前统一发行版本 0.1.0，使用 TypeScript / Node.js。此前 0.1.1 / 0.1.2 为未正式发布的实验编号；使用说明按 [README](../README.md) 分角色阅读。

## 目标和当前基础

近期优先完成“AI 编写并维护操作文档”，随后支持“小惠”部门试点。当前已具备配置、浏览器用户授权、scope 增量授权、token 刷新逻辑、通用 API、文档创建 / 追加 / 读取、JSON 输出和 Agent Skill。实测范围见[验收记录](ACCEPTANCE.md)。

## 下一阶段优先级

| 顺序 | 交付内容 | 完成标准 |
| --- | --- | --- |
| 1 | 同事指南、维护者指南、示例和试点接入方案 | 非维护者能按说明完成配置、本人授权和文档读写；明确密钥如何管理 |
| 2 | 有序列表、无序列表、代码块的 Markdown 写入与读取 | 一篇真实操作手册能正确保留步骤顺序、列表层级和命令格式；不支持语法有明确说明 |
| 3 | 写入失败恢复与结果核对 | 返回已创建文档、已确认批次和未确认范围；读取重试可控，写入结果不明时先核对，避免重复写入 |
| 4 | 按章节修改和修改预览 | 能定位目标章节、展示变更并更新；并发修改时能够发现冲突 |
| 5 | 表格和截图 | 参数表及操作截图能插入、读取或保留引用，并在昆仑实际接口上验收 |
| 6 | 文档查找与目录组织 | 按名称定位、指定目录创建等常用流程可用，并验证对应权限 |

顺序 1 已有统一无凭证安装包、交互式 config init、Skill 安装、分角色指南及独立试用空间；成员真实试点仍待验收。顺序 4 已实现唯一文本修改、版本检查和预览，复杂章节重排尚未实现。

长文档读取还需处理当前 20 页上限，避免达到上限后静默返回部分内容。复杂内容的读取应明确未支持的块类型，避免 AI 将不完整结果当成全文。

## “小惠”成员接入

### 近期：受控的本机 CLI 试点

成员使用同一个应用，每位同事在自己的运行环境中保存本人的用户登录态。维护者负责应用可用范围、用户身份 API 权限、程序版本分发和批准的密钥配置流程。

所有人使用同一无凭证安装包，通过本机 config init 配置 App ID 与隐藏输入的 Secret，再以本人账号授权。后续可接入系统密钥链改进本地存储；若希望同事完全不接触共享 Secret，则需托管授权服务。

### 后续：托管授权与聊天入口

若需要成员不接触应用密钥，或直接在“小惠”会话里请求任务，应单独设计服务端能力：

- 服务端保管应用密钥，按用户隔离 token，处理授权回调与刷新。
- 将聊天用户与授权用户可靠对应，拒绝使用其他成员的用户 token。
- 按用户授权和文档资源权限执行，写入前明确目标与内容。
- 处理任务结果返回、审计、失败恢复、成员退出和授权撤销。

这是待设计的服务端方案，不能仅把当前 `.kunlun-cli` 目录放到共享服务器上就视为完成。先选择受控 CLI 试点还是优先托管授权，再确定聊天功能排期。

## 其他办公能力

通讯录、日历、消息、审批、多维表格等保留为按需求扩展项。先确认昆仑文档、真实接口、所需身份及 scope，再实现业务命令。历史探活返回 400 只证明路由可能存在，不能作为功能验收结论。

每个阶段收尾需更新使用说明与验收记录，完成对应测试和真实场景验证，审阅 diff 后提交并 push。认证修复、文档完善、Markdown 支持等适合分别作为可追踪的提交节点。
