# 部门同事：用 AI 操作自己的昆仑文档

使用维护者提供的完整 Windows 安装目录（含 `kunlun-cli-0.1.0.tgz` 和安装脚本）。安装包不包含部门凭证；应用配置只需做一次，日常任务直接对 Agent 说。

## 首次接入

准备 Node.js 22.18+（推荐已验证的 24），连接办公网络，在安装包目录执行：

```powershell
.\install.cmd
```

程序自动安装到当前用户的 `%LOCALAPPDATA%\kunlun-cli`，自动添加用户 PATH。首次安装后完全退出并重新打开终端、Agent 应用（仅新建对话或终端标签页可能不够），再执行：

```powershell
kunlun.cmd --version
kunlun.cmd config init
```

向维护者领取批准使用的应用资料。在终端按提示输入 App ID 和 Secret，Secret 不回显。不要将 Secret 发到 Agent 对话中。维护者需将你加入“小惠”可用范围，并使当前 CLI 版本所需的用户身份权限生效。

在实际使用的 Cursor 项目目录中安装 Skill，然后重开 Agent 对话：

```powershell
kunlun.cmd skills install --dir .cursor/skills
```

其他支持 SKILL.md 的 Agent 使用它支持的技能目录；Agent 需具备本机终端工具并能执行 kunlun。

## 日常直接说需求

> 使用 kunlun-doc，帮我登录“小惠”。然后把下面的巡检流程整理成操作文档，创建到我的昆仑智联云空间，读回核对并给我文档 ID 和可用 URL。

Agent 会直接使用 `auth login` 请求版本固定权限，引导本人浏览器授权；你负责确认账号并同意，无需选择或补写 scope。以后可以说：

- 读取这篇文档，帮我总结注意事项：〈docx 链接〉。
- 找一下“泵站巡检规程”并总结注意事项；有同名文档时先让我选。
- 给这篇文档末尾补充今天的变更说明：〈内容〉。
- 把这篇文档中的“每周检查一次”改成“每天检查一次”，先给我看预览。

只记得名称时也可以先让 Agent 搜索；同名时需选择具体目标，不自动读取第一条。按名称直接读取只接受唯一完整标题及明确的新版 docx 类型；旧版文档正文暂不支持。当前支持三级标题与普通段落，已有文本修改须唯一匹配；删除、移动、重命名、截图和复杂表格尚未实现。若未配置文档网页根地址，结果可能只有 ID，没有 URL。搜索已按官方文档封装，实际环境仍需按[接口说明](SEARCH_API.md)验收。

读取复杂文档时，Agent 应说明完整性结果和被省略的内容范围；部分文本不代表全文。分页失败会返回部分结果，不能用它判断文档中某段内容不存在。

这是本机 Agent 调用 CLI，不是在昆仑“小惠”聊天窗口发指令。网络失败后先让 Agent 读回核对，不要盲目重复创建或追加。文档以本人身份访问，分享权限仍需单独设置。

## 更新与报障

同一安装包供所有人使用，更新程序保留本机配置。不同工作目录默认共用 `~/.kunlun-cli`。退出使用 `kunlun.cmd auth logout`；卸载程序不会清除全部凭证或云端文档。

更新时在新的交付目录再次运行 `install.cmd` 即可覆盖程序。CMD 中可用 `kunlun`，PowerShell 推荐 `kunlun.cmd`。固定路径已配置后，后续更新通常无需再改 PATH。Skill 是项目内的独立副本；需要更新时先保留自定义内容，再运行 `kunlun.cmd skills install --dir .cursor/skills --force`。

反馈版本、发生时间和脱敏错误即可，不发送密钥或 token。应用配置或版本范围外的权限需求联系维护者；新增权限随新版分发，升级后按提示重新授权。授权失败时提供页面错误，不反复追加 scope 重试。
